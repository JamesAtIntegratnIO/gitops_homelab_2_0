What did **not** move: the gate, `kargo-pipelines` and `kargo-observability`, which are still `delivery/`; Bosun is a component of that kit consumed from a registry now rather than a directory. **The wiring change is the substantive half.** The addon was a `path:` into this repository pinned to `defaultVersion: "main"` and an image tag of `main` — a branch name in both halves, so the running version was whatever the last build produced and no pin ever recorded it. It is now an ordinary OCI chart addon (`oci://ghcr.io/jamesatintegratnio/charts/bosun`, `defaultVersion: "0.1.0"`) with `image.tag` deliberately unset so the chart falls back to its own `appVersion` — one bump moves chart and image together and they cannot drift. Kargo tracks it as a new `bosun` target (`autoMerge: patch`, verified against `bosun-the-cluster`), where before it tracked nothing at all. Note what auto-merging that target means: Bosun is what triages gated pull requests, so a bad bump takes triage down with it and **the failure is silence, not an error** — the `verify` app is the only thing that catches it. **Operational consequence on merge**: the Application's source changes from a git path to a Helm chart, so ArgoCD replaces the source rather than diffing it; the rendered objects should be identical (same chart contents, same release name `bosun`, same `fullnameOverride`) and the only real change is the image reference moving from `ghcr.io/…/gitops_homelab_2_0/bosun:main` to `ghcr.io/…/bosun:0.1.0`. The `app.kubernetes.io/part-of: delivery-kit` label was **kept** — Bosun ships separately but is still that kit's component, and changing it would churn the label on every live object for nothing. The 1Password items (`delivery-agent-github`, `delivery-agent-llm`) are untouched, as before: renaming a component in git cannot rename an item in someone's vault. The nine replayed incidents moved with the eval fixtures they read, which is where they belong — their gate report is **recorded**, so they never needed the gate binary, Kargo or Prometheus, only Gitea and a model endpoint. The kit's own proving ground now pulls Bosun at the pinned version instead of building it, because this working tree no longer has the source. **Not yet verified**: nothing here is confirmed until it is on `main` and `bosun-the-cluster` reports Synced/Healthy on chart 0.1.0.
